Checklist


    
  
  1. Token + honeypot: view source of the mounted form — a hidden
    _osf_hp input exists; on submit the request carries a
    _osf_token (Network tab).
    2. 
  
  2. Submitting state: the button disables and shows a spinner
    while the request is in flight.
    3. 
  
  3. Success UX: a "Message sent" overlay covers the form; OK (or
    Esc) closes it to a "Send another" panel; focus is trapped in the
    dialog and returns to the form afterwards; osf:success logs.
    4. 
  
  4. Send another: restores a fresh, empty form and fetches a new
    token.
    5. 
  
  5. Field error: submit with an invalid email — an inline error
    attaches to the email field ONLY, the input keeps its value,
    osf:error (invalid_email) logs.
    6. 
  
  6. Form-level error: disable the form in the admin panel, then
    submit — a form-level error strip appears (unknown_form).
    7. 
  
  7. token_expired (invisible retry): lower
    TOKEN_MAX_AGE_SECONDS to a few seconds, load the form, wait past
    it, then submit — it should still succeed with no visible error (a fresh
    token is fetched and the submit retried once).
    8. 
  
  8. Turnstile (optional): for a form with Turnstile configured,
    the widget renders above the button; a failed challenge shows the form-level
    error and resets the widget.
    9. 
  
  9. Reduced motion: with the OS "reduce motion" setting on, the
    spinner does not animate.
    10. 
  
  10. No-JS guarantee: disable JavaScript and reload. The static
    fallback form above still renders; follow the no-JS fallback
    instructions it shows (or copy the key-filled snippet from “No-JS test
    snippet” captured while JS was on) and submit — the browser navigates
    to a readable page. (Delivery of a no-JS submission depends on the token
    policy — see QUESTIONS.md.)
    11. 
  
  11. UI suppressed: append &ui=none to the URL —
    no overlay/spinner/error UI renders, but the events still fire.
    12.
